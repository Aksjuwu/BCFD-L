<dash>
name: $returnGuildUsersID
desc: Collecte les IDs des membres humains (non-bot) d'un serveur et les stocke.
category: Commandes de retour

<block type="text" title="Comment fonctionne la commande ?">
text: $returnGuildUsersID collecte tous les IDs des membres humains (non-bot) d'un serveur spécifié et les stocke sous un nom de variable. Vous pouvez choisir entre le mode "cache" (utilise les membres déjà mis en cache) ou le mode "chunk" (force d'abord une récupération complète des membres du serveur pour des données complètes). Le résultat peut être récupéré plus tard avec $return[variableName].
</block>

<block type="code" title="Syntaxe">
text: $returnGuildUsersID[guildID; cache/chunk; var; separator]
</block>

<block type="code" title="Exemple prêt à copier">
text: $returnGuildUsersID[$guildID; cache; userIDs; ,]
$sendMessage[Users: $return[userIDs]]
</block>

<block type="options" title="Modes de récupération">
option: cache|Utilise la liste des membres mise en cache par le bot (rapide, mais peut être incomplète pour les grands serveurs)
option: chunk|Force d'abord une récupération complète de la liste des membres depuis Discord (plus lent, mais complet)
</block>

<block type="callout" kind="note">
text: Seuls les membres humains (non-bot) sont inclus. Le bot doit être membre du serveur cible. Utilisez le mode "chunk" pour les grands serveurs où la liste des membres en cache peut être incomplète.
</block>
</dash>

<details>
syntax: $returnGuildUsersID[guildID; cache/chunk; var; separator]
param: guildID|snowflake|Requis|L'ID du serveur dont il faut collecter les IDs des membres
param: cache/chunk|text|Requis|Mode de récupération : "cache" pour les membres en cache (rapide), "chunk" pour une récupération complète (complet)
param: var|text|Requis|Le nom de la variable dans laquelle stocker le résultat (à utiliser avec $return[])
param: separator|text|Requis|Le séparateur entre les IDs multiples (ex. : , ou ;). Vous pouvez utiliser des séparateurs nommés : dot, com, apo, sem, colon
</details>
